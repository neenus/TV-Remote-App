# Fire TV (ADB over Wi-Fi) Plan

> Executed inline, same process and review lessons as the Samsung plans.

**Goal:** Control Amazon Fire TV devices (the owner has a Fire TV Stick at 172.20.0.197) from the same remote UI.

**Approach:** ADB over TCP (port 5555), the standard way third-party remotes drive Fire TV. The stick must have **ADB debugging** switched on (Settings > My Fire TV > Developer options; Developer options is revealed by tapping the build number seven times in About). The first connection makes the stick show an "Allow USB debugging?" box that the user accepts with the stick's own remote; the app's RSA key is then trusted. The stick's own Bluetooth remote is unaffected.

**Evidence:** `172.20.0.197:5555` refuses connections (probed with the owner's permission: connect only, nothing sent), i.e. the stick is reachable but ADB debugging is off.

**Reference:** `adb_shell` (Python) in the scratch virtualenv generates golden vectors: message packing, the 24-byte header (command, arg0, arg1, length, checksum, magic), RSA key blob encoding (`encode_pubkey`), and token signing (`rsa.sign(..., 'SHA-1-PREHASHED')`).

## Protocol summary
- Message: 24-byte little-endian header `command, arg0, arg1, data_length, data_checksum (sum of bytes), magic = command ^ 0xFFFFFFFF`, then data.
- Handshake: send `CNXN` (version 0x01000000, max data, `host::\0`). The device answers `CNXN` (already trusted) or `AUTH` type 1 with a 20-byte token. Send `AUTH` type 2 with the token signed by our RSA key (PKCS#1 v1.5 over a SHA-1 DigestInfo built directly from the token, no extra hashing). If the key is unknown the device answers `AUTH` type 1 again: send `AUTH` type 3 with our public key (ADB blob, base64, + " user@host", NUL terminated); the device shows the Allow box and then answers `CNXN`.
- Commands: `OPEN` (local id, 0, `shell:<command>\0`), device replies `OKAY`; output arrives as `WRTE` (answer `OKAY`) and the stream ends with `CLSE` (answer `CLSE`).
- Keys: `shell:input keyevent <code>`; text: `shell:input text '<escaped>'` (space as `%s`).

## Decisions
- One RSA-2048 key per install, generated on first use in an isolate (several seconds) and kept in secure storage; the blob format is ADB's fixed 2048-bit struct.
- Supported keys: d-pad (19-22), OK (23), back (4), home (3), menu (82), volume up/down (24/25, control the stick, not the TV), mute (164), rewind/play/pause/fast-forward (89/126/127/90), power (26). Channel up/down and Input are not applicable.
- Typing is supported (a first: `input text`, backspace key 67, enter key 66). Fire TV does not announce text fields, so the keyboard panel is opened by hand and the "TV hasn't reported a text field" hint is not shown for it.
- Only one key command is allowed in flight; presses arriving meanwhile are dropped (each `input` call starts a process on the stick and held keys would pile up).
- Add-by-IP chip "Fire TV"; no discovery in this version.

## Tasks
1. **Codec + RSA** (`adb_protocol.dart`, `adb_auth.dart`): message encode/parse, token signing, public-key blob, key generation; golden vectors from the reference.
2. **Driver** (`fire_tv_driver.dart`): handshake (trusted / sign / allow prompt), streams, keys, typing, reconnect; all prior lessons (pending futures fail on close/dispose, stale sockets ignored, queued presses dropped, storage trouble tolerated, ack watchdog).
3. **Wiring:** `TvBrand.fireTv`, chip, factory, key map and capabilities (`announcesKeyboard`), setup instructions in the error text, checklist.
4. Review, fix pass, build, serve.

## Review Focus
1. Allow box declined or ignored: clear `PairingDenied` / timeout, nothing broken.
2. ADB debugging off or wrong port: the error tells the user how to enable it.
3. Socket drops mid-handshake / mid-command; dispose while generating the key.
4. Corrupt or oversize ADB frames from the network.
5. Shell injection through `input text` quoting.
6. Key generation: strength, storage format, run off the UI thread.
